## 파일 1: `1. 프레임워크(주요사업3)_Do.hwp`

성격: 경영실적보고서 "주요사업" 파트의 **작성 프레임워크(빈 템플릿)**. 대상사업 1~3, 세부과제(1-1 ~ 3-4)별로 「추진배경 → 추진내용/노력 → 추진실적 → 추진성과」 서사 구조를 표로 미리 짜 놓은 골격. 셀 대부분이 빈칸이며 라벨(추진배경·추진성과 등)과 불릿 기호(∙, -)만 자리표시로 남아 있음.

### 1-A. 대상사업 헤더 배너
- **용도**: 대상사업 단위 대제목 표시 (예: "대상사업 1. ICT기금 운용 고도화 (5p)" — 분량 지시 포함)
- **구조**: 3열 × 3행(위아래는 여백행), 가운데 셀에 제목 텍스트. 병합 없음
- **선택 기준**: 새 대상사업(챕터) 시작 시 맨 앞에 1회 배치
- **작성란**: 가운데 셀 1곳 — "대상사업 N. <사업명> (Np)" 형식

### 1-B. 세부과제 제목 바 (+뱃지)
- **용도**: 세부과제 번호·제목 표시 (예: "1-1 | ICT 정책의 안정적 뒷받침을 위한 재정위기 대응력 강화"). 제목 셀 안에 「B.P」, 「지적사항」, 「ESG-G」 등 미니 뱃지 표를 중첩해 과제 성격 태깅
- **구조**: 3열(번호 / 여백 / 제목) + 아래 여백행. 제목 셀 내부에 1행 2열 뱃지 중첩표(선택)
- **선택 기준**: 세부과제(N-N) 시작마다 필수. Best Practice·경영평가 지적사항 대응 과제면 뱃지 중첩표 포함
- **작성란**: 번호 셀, 제목 셀, (선택) 뱃지 표의 빈 셀

### 1-C. 추진배경 라벨 박스
- **용도**: 과제 추진배경 서술 (외부 환경·지적사항·정책 요구 등)
- **구조**: 5열 그림자 박스형(좌우·상하 테두리 여백열 + 라벨 셀 "추진배경" + 본문 셀). colspan으로 본문 폭 확보
- **선택 기준**: 각 세부과제 도입부에서 "왜 이 과제를 했는가"를 쓸 때 기본 선택
- **작성란**: 라벨 오른쪽 본문 셀 — ∙ 불릿 문장

### 1-D. 추진배경 3분할 표
- **용도**: 추진배경을 3가지 축(배경 1·2·3)으로 병렬 제시
- **구조**: 헤더행에 "추진배경 1 / 2 / 3" 3개 colspan 블록, 아래 각 블록에 ∙(주장)+-(부연) 불릿 슬롯
- **선택 기준**: 배경 요인이 명확히 3개로 구분될 때 (환경·정책·수요 등)
- **작성란**: 각 블록의 ∙ / - 불릿 셀 3쌍

### 1-E. 화살표 프로세스 표 (A→B→C)
- **용도**: 「지적사항분석 → 개선노력 → 개선결과」, 「분석 → 대응 → 성과」 등 인과 흐름 시각화. 이 파일의 핵심 반복 패턴
- **구조**: 3개(또는 2개) 콘텐츠 열 사이에 화살표 이미지 셀(rowspan 3~4) 삽입. 각 콘텐츠 열은 소제목 셀 + 본문 셀 세로 구성. 병합 많음(화살표 셀 rowspan, 외곽 여백 셀)
- **선택 기준**: "문제/지적 → 노력 → 결과" 인과를 한 눈에 보여야 할 때. 경영평가 지적사항 개선 실적 서술에 최적
- **작성란**: 각 단계의 소제목 셀 + 본문 불릿 셀 (화살표 셀은 고정)

### 1-F. 구분/추진노력/추진결과 표 (3열·4열 변형)
- **용도**: 세부활동을 항목별로 노력↔결과 대응시켜 나열
- **구조**: ① 3열형 `구분 | 추진노력 | 추진결과`, ② 4열형 `구분 | 추진노력 | 추진내용 | 추진결과`. 데이터 3행, 각 셀 ∙ 불릿 시작. 병합 없음 — 가장 단순한 반복 표
- **선택 기준**: 활동이 3건 내외로 나열 가능하고 각각 결과가 대응될 때 기본 선택. 노력·내용을 구분하고 싶으면 4열형
- **작성란**: 데이터 3행 전체 (구분=활동명, 나머지=∙ 불릿)

### 1-G. 추진성과 강조 배너
- **용도**: 세부과제 마무리 성과 요약 (정량 수치 강조). 예: "실무자 소통 간담회 00회 / 개선조치 00건"
- **구조**: 5열 그림자 박스(여백/라벨 "추진성과"/여백/본문/여백), 본문에 ∙ 불릿 2~3개. 「추진실적」 라벨 변형도 동일 구조
- **선택 기준**: 모든 세부과제의 맺음에 필수 — 성과를 2~3줄 정량 불릿으로 압축할 때
- **작성란**: 본문 셀의 ∙ 불릿 2~3개 (수치 포함 권장)

### 1-H. 추진실적 병렬 블록 표 (실적 1·2 / 1·2·3)
- **용도**: 복수 추진실적을 번호 블록("추진실적 1", "추진실적 2", …)으로 나란히 비교 제시
- **구조**: 2~3개 블록을 가로 배치, 각 블록 = 번호·제목 셀 + 본문 셀(rowspan 병합 다수), 블록 사이 구분 여백열. 좌측에 라벨 미니표(「추진실적」) rowspan 중첩 변형 있음
- **선택 기준**: 실적이 2~3개 트랙으로 대등하게 나뉠 때 (가로 비교가 자연스러운 경우)
- **작성란**: 각 블록의 번호 옆 제목 셀 + 본문 셀

### 1-I. 번호 소제목 사이드바 표
- **용도**: 추진내용을 「1 소제목 / 2 소제목 / 3 소제목」(예: "1 전담조직운영") 세로 목차와 우측 본문으로 구성
- **구조**: 좌측 rowspan 중첩표(번호+소제목 5행), 우측 본문 열(각 소제목당 ∙ 불릿 3개 슬롯). rowspan 병합 심함
- **선택 기준**: 추진내용이 3개 소주제로 나뉘고 각 소주제에 세부 불릿이 여럿일 때
- **작성란**: 사이드바의 소제목 3곳(OOO 자리) + 우측 ∙ 불릿 셀들

### 1-J. 구분/주요내용 2열 미니표
- **용도**: 추진내용 서술 중 제도·시스템 구성요소를 항목별로 정리 (「추진내용」 박스 내부 중첩용)
- **구조**: `구분 | 주요내용` 2열(4열 확장 변형 있음), 데이터 3행, 병합 없음
- **선택 기준**: 본문 불릿 아래에 항목-설명 대응을 깔끔히 붙일 때
- **작성란**: 데이터 행 전체

### 1-K. 우수사례 박스
- **용도**: 「우수사례1」「우수사례2」 라벨을 단 대표 사례 소개
- **구조**: 5열, 라벨 셀(rowspan 2)+내용 셀들. 2개를 연속 배치해 사례 2건 제시
- **선택 기준**: 정성적 대표 사례(수혜기업·콘텐츠 등)를 1~2건 부각할 때
- **작성란**: 라벨 우측 내용 셀들

### 1-L. 좌우 대비(분석→결론) 표
- **용도**: 「분석내용 강조 → 분석결과」, 「중국 등 현황 분석 → 신규사업 발굴」처럼 분석과 시사점을 좌우로 연결
- **구조**: 좌 블록 + 화살표 이미지(rowspan) + 우 블록. 1-E의 2단 축약형
- **선택 기준**: 단계가 2개뿐인 인과(분석→결론, 현황→대응)일 때
- **작성란**: 좌·우 블록의 제목·본문 셀

### 1-M. 이미지 4분할 갤러리 표
- **용도**: 활동 사진·캡처 4장을 캡션과 함께 배치
- **구조**: 4열 3행 (캡션행 / 이미지행 / 캡션행), 병합 없음
- **선택 기준**: 현장 사진 등 시각 증빙을 나란히 실을 때
- **작성란**: 캡션 셀 (이미지 셀은 그림 삽입)

## 파일 2: `2020년도 경영실적보고서 작성 활용 표 모음 (1).hwp`

성격: 경영실적보고서에서 재사용하는 **표 클립보드 모음집**. 문서 자체가 <체계도> <SWOT 분석> <우측 방향> <복합> <그래프> <아래방향> <일반> 섹션 제목으로 유형을 분류해 놓았음. 파일 1과 달리 서사 골격이 아니라 낱개 부품 창고.

### 2-A. 전략체계도 (비전-전략-과제 계층 그리드)
- **용도**: 미션·비전·전략방향·전략과제·세부과제의 계층 구조를 한 판에 표현 (기관 전체 또는 사업 단위 체계도)
- **구조**: 18열급 대형 그리드. 좌측 계층 라벨 열(rowspan 6+), 우측에 4개 과제 열 블록(colspan 2 단위) 반복. 병합 극심 — 사실상 표를 다이어그램 캔버스로 사용
- **선택 기준**: 챕터 첫 페이지에서 사업 추진체계 전체 조감이 필요할 때 (보고서당 부문별 1회)
- **작성란**: 계층 라벨 셀(비전/추진방향 등)과 각 과제 블록 셀 전부 빈칸

### 2-B. As-Is / To-Be 대비 표
- **용도**: 개선 전후 비교. 변형 2종: 「현행(As-Is) | → | 변화(To-Be)」(체계도 내부 중첩), 「종전(As-Is) | (여백) | 개선(To-Be)」(항목 3~4행 대응)
- **구조**: 좌 As-Is 열 + 중앙 전환 열(화살표/여백, rowspan) + 우 To-Be 열, 항목별 행 대응
- **선택 기준**: 제도·프로세스 개선을 "전→후"로 보여줄 때 표준 선택
- **작성란**: 좌우 대응 행 셀 (행 수 = 비교 항목 수)

### 2-C. 환경분석 3축 표
- **용도**: 「(내부) 경영여건 / (외부) 정부정책 / 이해관계자 니즈」 3개 관점의 환경분석 → 하단 시사점(R&R 재정립 + ✚ 결합 셀)
- **구조**: 12열, 상단 3개 관점 헤더 + 각 본문, 하단에 ✚ 기호로 요인을 결합하는 중첩표
- **선택 기준**: 과제 도출 근거로 대내외 환경을 구조적으로 제시할 때
- **작성란**: 3개 관점 본문 셀 + 하단 시사점 셀

### 2-D. SWOT 분석 표
- **용도**: SWOT 및 SO/WO/ST/WT 전략 도출
- **구조**: 4×6. 헤더 「강 점 (S) | 약 점 (W)」, 좌측 「기회(O)」「위협(T)」 rowspan 2, 교차 셀에 전략 라벨 "(SO) 강점기반, 기회활용" 등 4개 고정
- **선택 기준**: 사업·기관 단위 전략 수립 근거를 정식 SWOT으로 보일 때 (전략 라벨은 그대로 두고 내용만 채움)
- **작성란**: S/W 요인 셀, O/T 요인 셀, 4개 전략 셀

### 2-E. 추진 로드맵 표 (단기/중기/장기)
- **용도**: 「단기(ʼ19~ʼ20) / 중기(ʼ21~ʼ22) / 장기(ʼ23~ʼ24)」 시계열 추진계획
- **구조**: 좌측 「비전재해석」「추진방향」 세로 라벨(rowspan) + 구분행 + 기간별 colspan 열 3개, 과제별 행
- **선택 기준**: 중장기 계획·이행 로드맵을 시기 구간으로 나눠 보일 때
- **작성란**: 기간×과제 교차 셀, 비전 문구 셀(ㅇㅇㅇ 자리)

### 2-F. 기존/개선 + 태그 표
- **용도**: 기존 대비 개선사항을 「강화/유지/신규/개선」 태그로 분류 제시
- **구조**: 좌 「기존」 2열 블록 + 중앙 전환 열(rowspan 5) + 우 「개선」 블록(항목 + 태그 셀). 태그 4행 고정
- **선택 기준**: 지표·과제 개편처럼 항목별 변경 성격을 라벨링해야 할 때
- **작성란**: 좌우 항목 셀 (태그 라벨은 고정)

### 2-G. 가로 프로세스 표 (<우측 방향> 계열)
- **용도**: 좌→우 단계 흐름. 변형 다수: 「step① → step② → step③ → step④」, 4개 병렬 박스(ooooo), 2~3단 화살표 연결, 인풋+✚+인풋→아웃풋 결합형
- **구조**: 단계 헤더 셀 + 사이 연결 열(rowspan 2, 화살표/✚) 교차 반복. 하단 설명행 colspan
- **선택 기준**: 절차·추진단계·전달체계를 시간/논리 순서로 가로 배열할 때. 단계 수(2~4)에 맞는 변형 선택
- **작성란**: 각 step 제목·본문 셀 (연결 기호 셀 고정)

### 2-H. 미니 그래프 표 (텍스트 막대그래프)

**AI·시스템 구축 결과보고**에서 반복 관찰된 실물 패턴이다. 병합 없음 — 전부 생성 안전.

### 3-A. 과제개요 표
- **용도**: 추진 배경 절 말미에서 과제의 신원을 한 표로 확정 (누가·무엇을·언제·어디까지)
- **구조**: 2열 × 5행. 1열=항목 라벨, 2열=내용. 헤더행 `항목 | 내용`
- **행 구성(실측)**: 과제명 / 추진근거 / 제안·수행 / 대상·범위 / 추진기간
- **선택 기준**: AX 제안과제·파일럿처럼 **근거와 수행주체를 명시해야 하는 과제**의 결과보고.
  배경 서술(ㅇ 2개)만으로는 과제 신원이 흩어질 때 기본 선택
- **작성란**: 2열 5개 셀. 추진기간에는 진도율·완료 상태를 괄호로 병기 (`'26.5월 ~ '26.6월말
  (진도율 100% 보고)`)

### 3-B. 화면 캡처 표
- **용도**: 구현 결과를 실물 화면으로 제시 (`[ 서비스 구현 화면 ]`)
- **구조**: n열 × 2행. 1행=번호+화면명 캡션 셀, 2행=이미지 셀. 2열 또는 3열이 실측 관찰치
- **선택 기준**: 서비스·UI가 산출물인 과제는 관례적으로 포함. 화면이 2개면 2열, 3개면 3열
- **작성란**: 캡션 셀은 `① 규정 질의 응답`처럼 **번호+명사구**. 이미지 셀은 사용자 제공분만
  주입한다 — **하네스는 스크린샷을 촬영하지 않는다**(SKILL.md ①단계). 캡션 후보는 하네스가
  코드·기능 분석으로 제안하고, 파일은 사용자에게 요청한다. 미제공 시 이 표를 만들지 않는다
- **주의**: 이미지 규격 판정(`check_image_size.py`) 통과분만 주입. 붙임에 추가 화면을 둘 때는
  번호를 이어서 매긴다(본문 ①②③ → 붙임 ④⑤)

### 3-C. 진화 이력 표
- **용도**: 지금 구조가 왜 이렇게 됐는지를 표 하나로 설명 (`[ 윤문검수 구조 진화 ]`)
- **구조**: 4열 × 4행 내외. `단계 | 조건(모델·방식) | 측정값 | 결과`
- **실측 예**: `유형별 전수 검사 | EXAONE | 600회 | 탐지 52건, 중복·오탐 다수` → `문항당 1회
  호출 | gemma4 | 30회 | 처리시간 약 5배 단축`
- **선택 기준**: 시행착오를 거쳐 설계가 바뀐 과제. 최종 스펙만 나열하면 판단 근거가 사라지므로,
  **버린 안과 채택한 안을 같은 축으로 비교**해 선택의 정당성을 남길 때
- **작성란**: 각 행의 4개 셀. 측정값 열은 동일 단위로 통일해 증감이 읽히게 한다
- **변형**: 실험 비교형(`방식·모델 | 검출 | 형식 파싱 | 판정`)도 같은 골격 — 축만 바꾼 것
