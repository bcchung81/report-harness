② 해법의 적정성 15% · 대체재

이미 있는 것으로는 왜 안 됐나

서식 — 실측값을 프로파일 한 곳에 박아 두고 후처리가 매번 같게 적용한다. 어긋나면 검증이 잡으니 수정 왕복이 사라진다.

맥락 — 한 번 확인한 기관 지식은 다시 찾지 않는다. 원출처가 붙어 있어 오인식이 걸러진다.

시간 말고 줄인 것 — 담당자별 편차와 수정 왕복. 양식이 바뀌면 고칠 자리는 format-profile 한 곳으로 특정된다. 양식 개정 시 담당·인수인계 주체

② 해법의 적정성 15% · 재사용

가져다 쓴 것과 직접 만든 것

번들한 것은 라이선스 전문을 동봉하고 빌드가 원작자 고지와 상류 바이트 일치를 검사한다 — 하나라도 빠지면 패키지가 만들어지지 않는다.

③ 실제 작동 15% · 내부

변환은 다섯 지점을 지나고, 실패는 숨기지 않는다

무슨 데이터로 도는가 — 지난 아흐레 동안 실제 업무 보고서 5건이 이 경로로 나갔다. 이 자리 시연은 합성 샘플로 돌린다(실보고서 본문은 기관 내부 내용이라 띄우지 않는다) — 코드 경로는 같다.

④ 사용성 15%

실무자가 넘을 허들은 하나다

설치 0계정 추가 0 API 키 0교육 없음 망분리 제약 충족 — 전 구간 stdlib

처음 쓰는 사람이 결과를 얻기까지 실측 소요시간(1인 시연 계측)

⑤ 채택과 위험 15% · ⑥ 확산 전략 15%

왜 쓰게 되고, 어떻게 퍼지나

이탈이 생긴다면 변환이 실패해 마크다운만 손에 쥐는 순간이다 — 그래서 실패를 침묵시키지 않고 무엇이 어긋났는지 목록으로 돌려준다. 먼저 알릴 대상과 경로 — 부서 회의 · 내부 게시판 · 기관 간 협의체 중 택
