# report-harness 5분 기술 발표 — 설계

> 작성 2026-08-09. 대본 정본은 [`docs/talk/2026-08-09-5min-script.md`](../../talk/2026-08-09-5min-script.md).
> 이 문서는 그 대본이 왜 그 구성인지의 판단 근거를 남긴다.

## 1. 전제

| 항목 | 확정값 |
|---|---|
| 길이 | 5분 (낭독 1,292자 ≈ 4분 20초, 발표 속도 분당 300자 기준. 쉼·전환 포함 4분 40초~5분) |
| 청중 | 에이전트 도구(Claude Code·스킬·MCP)를 이미 쓰는 기술 청중 |
| 목적 | 설계 판단과 시행착오 공유 — 도구 도입 권유가 아니다 |
| 자리 | 단독 발표. 선행 세션 없음 |
| 용어 설명 | 0초. 스킬·훅·MCP를 그대로 쓴다 |

5분은 **메시지 하나 + 근거 둘**이 상한이다. 설계에서 가장 먼저 한 일은 담지 않을 것을 정하는
것이었다 — 4단계 파이프라인 상세, 게이트 UX, hwpx 후처리 내부, 웹앱 배포 경로는 전부 뺐다.

## 2. 핵심 메시지

> **축적은 저절로 되지 않는다. 쌓는 장치를 만들었으면 멈추는 장치도 같이 설계해야 한다.**

부수 메시지 하나를 마지막에 붙인다 — 검증 장치는 무엇을 검증하지 **않는지**가 더 중요하다.

## 3. 구성 선택 (A안 채택)

세 안을 놓고 A를 골랐다.

| 안 | 구성 | 채택 여부 |
|---|---|---|
| **A** | 자동화는 쉬웠고 축적이 어려웠다 — 하나의 서사로 관통 | **채택** |
| B | 설계 원칙 3개 순회(판단/실행 분리 · 산출 계약 · 복리와 상한) | 기각 |
| C | 실패 3건에서 나온 설계(R043 반입 반려 · 75자 · 검증 우회) | 기각 |

**A를 고른 이유.** 청중이 이미 에이전트 도구를 쓰므로 "파이프라인을 만들었다"는 정보가치가
낮다. 반면 규칙·메모리를 쌓아 본 사람은 대부분 그 축적이 썩는 것을 아직 겪지 않았거나
겪고도 원인을 모른다. 청중이 자기 `CLAUDE.md`·룰 파일을 떠올리며 듣게 되는 것이 이 발표의
유일한 성공 조건이고, A만 그렇게 만든다.

**B를 버린 이유.** 5분에 원칙 3개면 각 80초라 전부 표면만 훑는다. 나열은 기억에 남지 않는다.

**C를 버린 이유.** 세 사고의 층위가 서로 다르다(패키지 포맷 / 문서 규범 / 실행 강제). 5분 안에
공통 교훈으로 수렴시키려면 각 사고의 배경 설명이 필요한데 그 예산이 없다. 다만 75자 사고는
A의 ④비트로 흡수했다 — 세 사고 중 축적 서사에 정확히 맞는 하나다.

## 4. 비트 시트

| 구간 | 시간 | 역할 |
|---|---|---|
| ① 훅 | 0:00–0:10 | "어떻게 도는지가 아니라 틀렸던 것" — 기대 설정 |
| ② 만든 것 | 0:10–0:35 | 최소 맥락 + **"어렵지 않았습니다"** 전환 장치 |
| ③ 쉬웠던 절반 | 0:35–1:20 | 판단은 문서로/실행은 스크립트로. 청중과의 공통 기반 확인 |
| ④ 복리를 붙였다 | 1:20–2:00 | lessons → rules 승격 루프. 여기까진 성공담 |
| ⑤ 43 | 2:00–2:25 | 반전 시작 — 축적이 스스로를 무력화하는 순환 |
| ⑥ 75 → 35 | 2:25–3:15 | **최고점.** 틀린 규칙이 성실히 지켜져서 난 사고 |
| ⑦ 멈추는 장치 셋 | 3:15–4:05 | 근거 등급 · 값 드리프트 탐지 · 정기 통폐합 |
| ⑧ 가드도 거짓말한다 | 4:05–4:45 | 2차 반전 — 상한 장치 자신이 드리프트에 걸려 있었다 |
| ⑨ 마무리 | 4:45–5:00 | 교훈 2개 |

②의 "어렵지 않았습니다 → 진짜 어려웠던 건 그 다음"이 구조상 승부처다. 여기서 기대를 한 번
꺾어야 ⑤~⑧의 실패담이 자학이 아니라 발견으로 들린다.

⑧을 마지막이 아니라 ⑦ 뒤에 둔 것은 의도적이다. 해결책(⑦)을 제시하고 곧바로 그 해결책의
구멍(⑧)을 보이면, 마무리의 "무엇을 검증하지 않는지" 문장이 결론이 아니라 관찰로 착지한다.

## 5. 슬라이드 9장

타이틀 → 파이프라인 1줄 → 판단/실행 분리 → 복리 루프 → `43` → `75 → 35` → 상한 장치 3개 →
`70 / 60, 초록` → 마무리 한 줄.

숫자 슬라이드 3장(`43`·`75→35`·`70/60`)이 기둥이다. 시각 스타일은 다크 테크니컬(무채색 4단계
밝기 + 액센트 1회)을 전제로 하며, 액센트는 **슬라이드당 한 번**만 쓴다. 숫자 슬라이드에서는
그 액센트를 숫자 자신에게 준다.

## 6. 수치 검증

대본이 인용하는 모든 수치는 저장소에서 대조했다(2026-08-09).

| 수치 | 출처 | 확인 |
|---|---|---|
| 두 달에 43건 | `README.md` | ✓ |
| 1줄 75자 → 실측 35자(중앙값 35·최대 47) | `rules-seed.md` R062 | ✓ |
| 넉 달 · 3~4줄 · 쪽수 2배 | `README.md` · `rules-seed.md` 표기 규약 | ✓ |
| 같은 값 최대 8곳 복제 | `README.md` (R066) | ✓ |
| 통폐합 임계 10건 | `rules-seed.md` R068 | ✓ |
| 현재 70건 · 최대 R071 · R050 결번 | `rules-seed.md` | ✓ |
| 70건 중 60건 본문 불일치 | 2026-08-09 감사 결과 (0.4.0에서 해소) | ✓ |

⑧비트의 60건 드리프트는 **발표 시점 기준 이미 해소된 상태**다(0.4.0에서 시드 재동기화 +
가드를 본문 비교로 강화). 대본은 이를 과거형으로 서술하며, 질문이 나오면 "고쳤고 가드도
본문 비교로 바꿨다"고 답한다 — 미해결 문제를 자랑하는 것으로 들리면 안 된다.

## 7. 범위 밖

- 라이브 데모 — 5분에 환경 리스크를 감수할 이유가 없다. 화면은 정적 슬라이드만.
- 하네스 홍보·설치 안내 — 저장소 주소는 마지막 슬라이드 하단에 작게만.
- claudian 위키 연동, 웹앱 배포판, hwpx 반입 반려(R043) — 전부 다른 발표의 소재다.
