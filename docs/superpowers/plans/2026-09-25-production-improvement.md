# 프로덕션 분석 기반 하네스 개선 계획 ('26.9.25)

> 목표: 운영 기록(lessons 330여 건·규칙 94번까지·작업폴더 17건)에서 반복되는 손실을 찾아 결정론으로 막고,
> 설치자(팀원)에게 개선이 실제로 도달하게 배포 경로를 고친다. 완료 기준은 전체 테스트·배포 가드·웹앱 빌드 통과,
> kordoc 실변환 검증, 배포 저장소 push와 CI 녹색.

## 2. 실행 항목

- **P1 compare 오탐 제거** — 짝이 맞는 볼드 역표현·원문 제목과 같은 첫 줄 `#`·따옴표 차이·되읽기 머리 블록을
  위반에서 뺀다. 짝이 안 맞는 `**`·원문에 없는 헤딩은 계속 잡는다.
- **P2 결함 정비** — 라벨 열 한 줄 폭 보장, 린트 훅은 `20_draft.md`만(플러그인 hooks로 편입), 같은 프로세스의
  새 세션은 임대를 넘겨받는다.
- **P3 lesson 스키마** — `kind`(content·defect·feature·preference)·`resolved_by`(커밋·R번호). 자가진단은
  결함·기능 중 미해결만 센다.
- **P4 배포 경로** — `sync_rules.py`: 시드에만 있는 규칙을 운영본에 덧붙이고 본문이 달라진 규칙은 보고만(설치자
  로컬 규칙 보존). 버전 0.5.0·CHANGELOG·README 정리.
- **P5 실물 검증** — kordoc MCP로 운영 초안 사본을 실제 변환해 새 도식 표(부호 뒤 탭·내어쓰기)와 compare 수정을 확인.
- **P6 배포** — 기능 묶음별 커밋, origin·배포 저장소(kca-deep) push, CI 확인, 릴리스 노트.

## 3. 공개 범위

문서 작성에 필요한 데이터(규칙 시드·참조 문서·양식 자산·파생 패턴)는 모두 저장소에 있다. 기관 양식 원본
(경영관리 프레임워크 12건)·실보고서·운영 교훈은 CLAUDE.md '저장소 경계'대로 올리지 않는다 — 런타임은 원본을
읽지 않고, 원본에서 뽑은 패턴(표·도식 틀)은 `table-pool.md`·`diagram-pool.md`·`md-profile.md`에 이미 공개돼 있다.

## 4. 결과 ('26.9.25 17시 기준)

P1~P6 전부 완료. 배포 저장소에 0.5.0 → 0.5.3을 내고 첫 GitHub 릴리스(`report-harness--v0.5.1`~`v0.5.3`, 웹앱 패키지
5종 첨부)를 만들었다. 계획에 없던 것으로 드러나 함께 고친 것:

- **설치자에게 실제로 도달하는지** — 격리 설정 폴더(`CLAUDE_CONFIG_DIR`)로 배포 저장소를 설치·갱신해 재현했다. 옛 시드
  줄을 '번호 충돌'로 오판(→ 시드 계보), 경위 로그·통합 마커 미동기, 같은 버전이면 `claude plugin update`가 새 커밋을
  받지 않음(→ 배포 묶음마다 버전 올림·가드 경고)을 찾았다.
- **실전 점검(`scripts/smoke_pipeline.py`)** — 헤드리스 세션으로 가상 자료 → 초안 → hwpx 전 구간을 2회 돌렸다(각
  약 9분·$4). R054 절 어휘 경고, '끝.' 없는 문서의 머리말 그림 오계수, 승인 뒤 쪽수 맞추기 압축, nbSpace run의 괄호
  축소 누락을 찾아 고쳤고, 2회차에서 승인 뒤 압축 금지·제목 한 줄 경고가 실제로 먹히는 것을 확인했다.
- **코드 리뷰 4회** — 오늘 변경분의 결함을 회차마다 고쳤다(규칙 동기화 덮어쓰기·임대 인계·같은 출처·검사 오탐 등).

**규칙 문맥 비용(보류 유지) — 측정.** 후처리가 자동으로 강제하는 [export] 전용 규칙(R043·R061·R063·R084) 본문을
머리말로 줄이는 안전한 기계적 슬림화는 [export] 사전 읽기의 7%(24,372 → 22,566자)에 그친다. 넓게 잡은 안(22%)은
LLM이 직접 판단·호출해야 하는 규칙(R067 쪽수 보고·R072 레시피 적용·R073 개정 건 제자리 수정·R088 도식 렌더)까지
잘라 쓸 수 없다. 규칙 본문의 근거 꼬리는 10% 수준이다. 실질 절감은 사람이 규칙 본문을 다시 쓰는 일이고, 그때
`python3 scripts/smoke_pipeline.py --runs 3 --rules <슬림판>`으로 현행과 A/B한다. 공통 규칙([draft][export] 10건)
중복 읽기만 절차로 줄였다(SKILL §0-5).
