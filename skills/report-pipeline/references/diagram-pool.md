# 도식 Pool — 표 도식·이미지 도식 선택 카탈로그

> 출처: `form/양식(표)/2. 도식 Pool.hwpx` (2024.11, 2단~5단 도식Pool 정의서. 2026-07-22 kordoc 분석).
> **번들 사본**: `skills/report-pipeline/assets/도식Pool-경량.hwpx` (이미지 제거 103KB — 표 원형
> 90개 파싱 가능, 배포 환경에서 원본 form/ 부재 시 이것을 쓴다). 번들 사본도 없으면 이 문서의
> 판정표 + md-profile 규격 GFM 표 재구성만으로 완결 동작한다(치환 필수 아님 — graceful degrade).
> **대원칙: 도식은 두 갈래 중에서 고른다('26.9.24 개정 — 종전 "SVG·이미지를 그리지 않는다").**
> ① 칸과 칸의 관계가 표로 충분하면 **표 도식** — 이 Pool에서 논리전개 구조에 맞는 표 패턴을 골라
> 작성란(슬롯)을 채운다(원형은 위 hwpx에서 발췌, 빈 셀 = 작성란). ② 화살표·연결선·기간 막대가
> 있어야 읽히는 흐름·비교·체계·일정은 **도식 명세** — `figures/{슬러그}.json`에 슬롯만 쓰고 모양은
> 스크립트가 정한다(아래 §이미지 도식). 종전 원칙을 바꾼 이유: GFM 표는 셀 병합을 못 해 Pool 원형이
> 재현되지 않았고(실사용 0건), 화살표가 필요한 도식은 표로 그릴 수 없었다.
> **흐름·비교·체계·일정 4유형은 변환에서 한글 표로 들어간다('26.9.25 R089)** — `diagram_table.py`가 같은
> 명세를 좌표 격자로 조립해 그림을 갈아 끼운다(카드 = 테두리 셀, 화살표 머리 = 셀 안 삼각형 도형 — Pool
> 원본과 같은 방식, 연결선 = 선만 있는 셀). 한글에서 글자를 바로 고칠 수 있고 흐려지지 않으며 그림보다
> 낮다. 나머지 유형(pdca·strategy·stack·image)과 명세에 `"render": "image"`를 준 도식은 300dpi 그림으로 남는다. 어느 쪽이든 **도식 내용은 본문 개조식에도 적는다** — 이미지는 기계가 읽지 못하고,
> 행안부 「AI시대 행정문서 작성 가이드라인」('26.3)도 복잡한 셀 병합을 금한다. 생성형 이미지(그림
> 생성 AI)로 도식을 만들지 않는다 — 글자·수치가 변형되고 원문이 외부로 나간다.

## 선택 절차 (LLM 판정)

1. 도식화할 내용의 **논리전개 구조**를 판정한다: 도입(배경) 유무 / 전개 항목 수 / 결과가 하나인가 여럿인가 / 강조 대상.
2. 아래 판정표에서 조건이 맞는 패턴을 고른다. 복수 후보면 **단수가 적은 쪽**(단순한 쪽)이 가독성 우선.
3. 슬롯별 입력 텍스트를 본문·근거에서 추출한다 — 셀 텍스트는 명사구 위주로 짧게(1~2행), 본문 문장을 그대로 붙이지 않는다.
4. 게이트①(목차) 단계에서 "이미지 배치/도식 설계" 절에 선택 패턴·슬롯 내용을 함께 제시해 승인받는다.

## 판정표

| 패턴 | 구조 | 선택 조건 (정의서 명시) |
|---|---|---|
| 2단 (2단-1~4) | 전개(추진내용) → 마무리(추진실적) | 배경·목적·원인·문제점 등 도입부가 부실해 3단을 못 쓸 때. **가급적 지양** |
| 3단-1 | 도입 → 전개 → 마무리 | 전개가 프로세스·전개형으로 진행되어 하나의 결과를 도출할 때 |
| 3단-2 | 도입 → 전개 → 마무리 | 추진배경이 3가지로 구분되고 추진내용의 수준이 같을 때 |
| 3단-3 / 3단-4 / 3단-11 / 3단-12 | 도입 → 전개 → 마무리 | 현황·문제점의 원인은 여러 가지인데 성과는 한 가지로 제시 가능할 때 |
| 3단-5 | 도입 → 전개 → 마무리 | 추진배경이 순차 프로세스로 표현되거나, 주요 성과가 전개 전체에 공통으로 제시될 때 |
| 3단-6 | 도입 → 전개 → 마무리 | 배경·내용을 인포그래픽 등으로 추가 설명이 필요할 때 |
| 3단-7 | 도입 → 전개 → 마무리 | 도입부(목적·원인·문제점) 강조 + 추진내용↔추진실적이 1:1 매칭될 때 |
| 3단-8 | 도입 → 전개 → 마무리 | 추진배경을 정부정책·경제현황·국민니즈 등 나열식으로 쓸 때 |
| 3단-9 | 도입 → 전개 → 마무리 | 추진내용이 사실 위주로 분량이 많을 때 |
| 3단-10 | 도입 → 전개 → 마무리 | 사실 위주 분량 많음 + 실적·성과를 한 가지 결과로 도출(결과 강조 시 짙은 음영) |
| 4단-1 | 배경 → 전개 → 실적 (+강조단) | 전개(추진내용) 중 우수사례 등 강조가 필요할 때 |
| 4단-2 / 4단-3 | 배경 → 전개 → 실적 (+강조단) | 정의서에 선택 조건 미기재(예시 표만 존재) — 4단-1 조건에 안 맞는 4단 구조에서 형태로 판단 |
| 5단-1 | 배경 → 내용 → 실적 → 우수사례 → 성과 | 추진실적·우수사례 중 전년도 지적사항 개선 반영을 보여줄 때 |

## 부속 자산 (같은 파일 내)

- **일러스트**: 부등호·화살표(흰 바탕용/음영 바탕용), 강화·Tip·참고·질의/답변 아이콘, 방향별 화살표 세트
- **다이어그램**: 격자 배치형, 개선 전→후 비교형(가운데 화살표), 흐름 연결형

## 작성 규칙

- 도식 표도 md-profile 표 규격의 예외가 아니다 — hwpx 주입 시 원형 표 구조(병합 포함)를 도식 Pool 파일에서 복제해 쓰되, md 초안 단계에서는 `도식: {패턴ID}` 마커 + 슬롯 내용 목록으로 표기하고 변환 단계에서 치환한다.
- 슬롯 내용도 팩트체크 대상 — 본문 근거와 불일치하는 텍스트를 도식에만 넣는 것 금지.

## 이미지 도식 (`render_diagram.py`)

명세는 `{work_dir}/figures/{슬러그}.json` — 사람이 고치는 원본이라 작업폴더 루트 폴더에 둔다(R087).
본문에는 캡션 `[ 제목 ]` 줄과 `도해: {슬러그}` 줄만 쓴다. 리뷰 HTML(게이트②)은 같은 명세로 도식을
그 자리에 그리고, 변환(④)은 `{판본폴더}/figures/fig{NN}.png`(300dpi)와 같은 이름의 HTML을 만든다.
**표 도식(R089)**: 아래 표의 flow·compare·structure·timeline은 변환 때 `diagram_table.py`가 그림을 한글 표로
바꾸고, 리뷰도 같은 표로 그린다(모양·높이·쪽 추정이 인도본과 같다). 캡션 `[ 제목 ]` 줄은 후처리가 표 캡션으로
넣고, 도식 표는 쪽에서 나누지 않는다. 그림으로 두려면 명세에 `"render": "image"`.

| type | 쓰는 때 | 슬롯 |
|---|---|---|
| `flow` 단계도 | 순서가 있는 단계 2~6개, 끝에 하나의 결과 | `steps: [{head, body[]}]`, `result: {head, body[]}`(선택) |
| `compare` 비교도 | 현행→개선, 종전→이번처럼 두 상태의 대조 | `left: {head, body[]}`, `right: {head, body[]}`, `arrow`(가운데 블록 화살표 몸통의 글자 — 표 도식은 몸통 셀 + 삼각형 머리. 라벨을 어절마다 한 줄로 세우고 화살표 크기는 라벨 높이로 정해, 줄인 폭만큼 좌우 카드가 넓어진다 — 2어절 이내 권장) |
| `structure` 추진체계도 | 상위→하위 층 구조(주관·참여·지원, 입력→경로→검증) | `levels: [[{head, body[]}…]…]` — 2~4층, 층마다 1~6개 |
| `timeline` 추진일정 | 기간 열 × 과제 행 | `periods: []`, `rows: [{task, span: [시작, 끝], note}]`, `task_ratio`(과제 열 %, 기본 34) |
| `pdca` 이행체계 | 계획 → 실행 → 점검 → 환류 순환(경영관리 프레임워크 이행체계 틀) | `phases: [{head, body[]}×4]`, `feedback`(선택, 환류 띠) |
| `strategy` 전략체계도 | 비전 → 경영목표 → 전략목표 N열 → 전략과제 | `vision`, `goals[]`(선택), `pillars: [{head, items[]}]` 2~5열, `base`(선택), `labels`(라벨 바꾸기) |
| `chart` 인용 차트 | 외부 자료의 시계열·기관 간 비교 수치(R092) — 이미지로 들어간다 | `kind`(`bar`·`line`), `categories[]` 2~12, `series: [{name, values[]}]` 1~4, `unit`, `highlight`(강조 범주 번호, 선택), **`source` 필수** |
| `stack` 라벨 블록 체계표 | 왼쪽 라벨 칸 + 내용을 ▽로 이어 가는 체계표(설립목적 ▽ 진단 ▽ 개선) | `blocks: [{label, body[]} 또는 {label, cols:[{head, body[]}]} 또는 {label, emphasis:true, body[]}]` 2~6개 |
| `image` 그림 참조 | research 그림(원문 도표·화면) | `src`(작업폴더 기준 경로) — 픽셀 그대로 복사(R088) |

공통 슬롯: `caption`(alt·목록용), `width_mm`(기본 169 = 본문 폭 − 1mm, 30~169), `render`(`"image"`면 4유형도 그림으로 — 기본은 표).

```json
{"type": "flow", "caption": "측정 체계 흐름",
 "steps": [{"head": "과제 배정", "body": ["기능 13분류 중 주기능 1개로 과제 배정", "18건은 배정하고 2건은 처리 건수만 관리"]},
           {"head": "성과 유형", "body": ["6개 질문으로 성과 유형 판정", "절감·품질·위험·상담 4개 유형으로 분류"]}],
 "result": {"head": "기관 보고", "body": ["AI 처리 업무량·순절감 시간으로 기관 실적 보고"]}}
```

- **글자**: 상자 제목은 명사구. **본문 항목은 서술형 문장**(R093) — 무엇을 어떻게 하는지를 목적어와 동작명사로
  끝맺는다(`기능 13분류 중 주기능 1개로 과제 배정`). 숫자로 끝나는 나열(`과제당 3개, 18건 54개`)·등호 정의식
  (`처리시간 = …`)은 쓰지 않는다 — 산식은 도식 아래 1열 표로(R064). 칸 이름·필드 목록 같은 기술 사양도 늘어놓지
  않고 무엇을 기록하고 어떻게 받는지로 쓴다(사양 전문은 붙임 표로). 초안의 `도해:`가 가리키는 명세를
  `audit_style.py`가 읽어 `diagram-fragment`·`diagram-formula`로 경고한다. 두 줄 이상으로 넘어가면 둘째 줄은
  첫 줄 글자에 맞춰 내어 쓴다 — 스크립트가 맞추므로 공백으로 흉내 내지 않는다. 본문에 없는 사실을 도식에만
  넣지 않는다(팩트체크 대상).
- **같은 줄 카드는 항목 수를 맞춘다**: 흐름도 단계·비교도 좌우·체계도 같은 층의 카드가 2개면 전부 2개,
  3개면 전부 3개 — 다르면 `render_diagram.py`가 거부한다('26.9.24 게이트② 지적, 들쭉날쭉하면 나열로 읽힌다).
- **결과 칸(flow `result`)은 핵심 한두 줄**: 전하려는 결론을 개조식 1~2줄로 쓴다 — 가운데·굵게·크게(12.5pt)
  그려진다(목록 점 없음). 다른 카드도 `"emphasis": true`를 주면 같은 강조로 그린다(체계도의 마지막 층 등).
- **숫자만 적지 않는다**: `1행 10칸`처럼 수치만 남기면 뜻이 전달되지 않는다 — 무엇을 적는 양식인지·어떤 칸인지를 쓴다.
- **모양은 스크립트가 정한다**: 배치·색(남색 #1B1760·청색 #0080C0 — 머리말 배너·제목 박스와 같은 색)·
  글자 크기(11pt)·연결선은 고정이다. LLM은 슬롯만 쓴다(매번 같은 결과, scripts/ 소관).
- **서체**: 맑은 고딕(표 서체). PC 폰트 폴더와 설정 `font_dirs`에서 찾고, 없으면 대체 서체로 그린 뒤
  `font_fallback: true`로 알린다 — 기관 폰트는 저장소에 넣을 수 없다. 기관 PC에서 다시 그리면 본문
  표와 같은 서체가 된다.
- **캡처**: Chrome·Edge·Chromium 헤드리스(설치된 것, `CHROME_PATH`로 지정 가능). 외부 URL 없음.
- **웹앱판**: 브라우저를 띄울 수 없어 이미지 도식을 쓰지 않는다 — 표 도식만(의도적 분기). `diagram_table.py`도
  하네스 전용이다(웹앱 md2hwpx는 `도해:` 마커를 다루지 않는다).
- **양식 틀 대응**: 경영관리 프레임워크('24.12.3)의 도식 틀이 어느 type에 대응하는지는 `table-pool.md` 파일 4 끝의 대응표.

## 외부 자료 인용 — 본문 문구 + 도식·표·차트 (R092)

research의 외부 자료에서 **인용이 필요한 내용**(통계 수치·기준·정의 원문·제도 구조·도표)은 두 가지를 함께 넣는다
('26.9.25 사용자 지시). ① **본문 문구** — 그 인용이 우리 논지에 무엇을 뜻하는지를 한 문장으로. 쉬운 말·두괄식
(style-guide §11, R091)을 똑같이 적용한다: 결론 먼저, 수치는 항목 뒤 괄호(R065), 기술어는 업무어로. ② **시각화** —
아래 형식 표로 고른 도식·표·차트. 그리고 ③ **출처 ※ 줄**. 문구 없이 도식만 두지 않는다(도식은 기계가 읽지
못하고, 읽는 사람도 무엇을 보라는지 모른다).

**분석 단계(05_analysis.md)에 '인용 재료 목록'을 만든다** — 게이트①에서 아웃라인과 함께 승인받는다.

| 인용 재료 | 시각화 | 명세 |

| 시계열·기관 간 비교 수치 | **인용 차트** — 막대(비교)·꺾은선(추이). 값은 막대·점마다 숫자로 | `{"type": "chart", …, "source": "research/{원본}"}` |
| 구조·절차·체계(원 도표) | 재작도 도식(아래 '외부 도식 활용') | 해당 type + `"source"` |
| 기준·정의 원문(법령·지침 문장) | 원문 인용 블록(md-profile §1-6, 25줄 이내) 또는 문구 안 「」 인용 | ```` ```text ```` |
| 항목이 많은 비교·목록 | 표 재구성 | 마크다운 표 |
| 사진·화면·원형 그대로 인용할 공식 도식 | 차용(원본 그림) | `{"type": "image", "src": …}` |

- **출처 ※ 줄 규격**: `※ 자료: {기관}, 「{자료명}」({연도}), {쪽}쪽` — 통계는 기준시점(`'25.12월 기준`)을 붙이고,
  우리가 다시 계산·재배열했으면 `재구성`·`재계산`을 쓴다. 차용(원본 그대로)은 `※ 출처:`. 여러 출처는 `;`로 잇는다.
- **이용 조건(저작권)**: 공표된 저작물은 목적·범위가 정당하고 공정한 관행에 맞으면 인용할 수 있고(저작권법
  제28조), **출처 명시는 의무**다(제37조 — 어기면 제138조 벌칙). 국가·지자체가 업무상 공표한 저작물은 허락 없이
  쓸 수 있다(제24조의2 — 국가안전·사생활·다른 법률상 비공개는 예외). 공공기관·민간 자료는 **공공누리 유형**을
  확인한다 — 제1·2유형은 재작도·재구성 가능(출처 표시), **제3·4유형(변경금지)은 재작도하지 않고** 원형 차용 또는
  문구 인용(필요한 부분만)으로 쓴다. 표시가 없는 민간 자료는 인용 범위(우리 글이 주, 인용이 종)를 넘지 않는다.
- **팩트체크**: 도식·차트 명세 안 수치도 경량 팩트체크 대상이다 — `validate_hwpx.py numbers`가 `figures/*.json`의
  글자·차트 값까지 research와 대조한다. 차트 명세는 `source`가 없으면 그려지지 않는다.

## 외부 도식 활용 — 차용·재작도·표 재구성

research에 모인 외부 자료의 도식(가이드라인 그림·보고서 개념도 등)을 본문에 쓰는 방법은 셋이다
('26.9.24 사용자 요청). 먼저 후보와 출처·해상도를 뽑는다:

```
python3 "$SKILL_DIR/scripts/list_research_figures.py" {work_dir}
```

그림마다 `title`(원 캡션)·`source_url`·표시 크기·유효 dpi·`sharp`와 권고가 나온다. 원본 그림은 Read로
직접 보고 아래 표로 정한다.

| 도식 성격 | 방법 | 명세 |
|---|---|---|
| 행×열 격자(로직모형·지표 매트릭스·단계별 배치표) | **표 재구성** — 우리 표로 옮긴다 | 마크다운 표 + 병합 표기(`A > B` 2단 머리행·`〃`·첫 열 굵게 라벨 열, md-profile §1-2) |
| 흐름·비교·계층·일정·순환·전략체계 | **재작도** — 우리 도식으로 다시 그린다 | `figures/{슬러그}.json` 해당 type + `"source": "research/{원본}"` |
| 사진·화면 캡처·데이터 차트·지도(구조로 옮길 수 없는 것), 원형 그대로 인용해야 하는 공식 도식 | **차용** — 원본 그림을 싣는다 | `{"type": "image", "src": "research/{원본}"}` — `sharp`가 참일 때만 |

- **재작도가 기본이다.** 원본을 그대로 실으면 색·글꼴·원 캡션('그림 13')이 우리 양식과 달라 튀고, 글자가
  작아 인쇄에서 읽히지 않는 경우가 많다. 재작도할 때 원본의 상자·화살표·층을 슬롯으로 옮기되, **우리
  문서의 논지에 필요한 부분만** 가져온다(원본 전체를 옮기지 않는다). 같은 줄 카드 항목 수 맞춤 등 위 작성
  규칙이 그대로 적용된다.
- **흐린 그림(`sharp: false`)은 차용하지 않는다** — 재작도하거나, 원문 PDF가 `sources`에 있으면 해당 쪽을
  고해상도로 다시 뽑는다(kordoc `crop_regions`). 규격 축소본(`scaled-` 등 96dpi 사본)은 쓰지 않는다(R088).
- **출처는 본문 ※ 줄이 맡는다** — 캡션 줄에는 쓰지 않는다. 차용은 `※ 출처: {기관}, 「{자료명}」({연도})`,
  재작도·표 재구성은 `※ 자료: {기관}, 「{자료명}」({연도}) 재구성`. 원 캡션 번호('그림 13')는 우리 캡션
  `[ 제목 ]`으로 바꾼다. 재작도 명세의 `source`는 변환 결과(`41_figures.json`)에 `source`·`source_ok`로
  남는다 — 출처 ※ 줄이 빠졌는지 확인하는 재료다.
- **팩트체크**: 재작도·재구성한 도식의 수치·명칭은 원본과 대조한다(factcheck §B).
