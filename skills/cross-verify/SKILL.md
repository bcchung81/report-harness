# cross-verify — 다중 CLI 교차검증

**핵심**: 여러 모델의 답을 나란히 보는 것이 목적이 아니다. **패널이 지어낸 근거를 걸러내는 것**이
목적이다. 범용 다중모델 도구는 패널 답변을 그대로 통과시키므로, 날조된 수치가 그대로 보고서로
넘어간다. 이 스킬은 3단계에서 그것을 잡는다.

경로 규약: `SKILL_DIR` = 이 SKILL.md가 있는 디렉토리. 스크립트 호출은 `"$SKILL_DIR/scripts/…"`
형태다 — 저장소 상대경로를 쓰면 플러그인 설치 환경에서 깨진다.

## 언제 쓰나

- 보고서 초안·설계안·기준안을 **인도 전에** 다른 모델 눈으로 검증할 때
- 내 판정에 확신이 안 설 때 (특히 "이 계획이 현실적인가" 류)
- report-pipeline ③draft 게이트② 직전, 또는 ④export 팩트체크의 보강

**쓰지 않는 경우**: 단순 사실 조회, 코드 리뷰(`/code-review`가 낫다), 원문 파일이 없는 열린 질문
(대조할 근거가 없으면 3단계가 무의미하다).

## 준비 — 패널 가용성

```
command -v agy codex
```

없는 패널은 건너뛴다. **한 개도 없으면 이 스킬을 쓰지 않는다** — 교차가 성립하지 않는다.
1개만 있으면 그 패널 + 메인 컨텍스트(나) 2자 교차로 진행하고, 인도 시 1줄로 고지한다.

## ① 패널 소집

**원문 전문을 프롬프트에 인라인한다.** 파일 경로를 주지 않는다 — 패널마다 파일 접근 권한·
샌드박스·cwd가 달라 "못 읽었다"로 갈리고, 그 사실이 답변에 드러나지 않아 빈손 판정이 정상
판정처럼 섞인다.

작업 파일을 만든다 (`{scratch}` = 임시 폴더):

```
{scratch}/q.md   = 판정 지시 + 원문 전문
```

지시에 반드시 넣는다:

| 항목 | 문구 |
|---|---|
| 근거 강제 | "문서 안의 표·각주·산식을 인용해 근거를 대라. 일반론·낙관 금지" |
| 판정 형식 | 판정 한 줄 → 항목별 표(대상·판정·핵심 리스크) → 치명적 결함 Top N(각각 원문 인용) |
| 미상 처리 | "문서에 없는 값은 추정하지 말고 '문서 미기재'로 적어라" |

마지막 항목이 없으면 패널이 빈칸을 지어낸 값으로 메운다.

두 패널을 **한 메시지에서 병렬 백그라운드로** 띄운다(직렬로 돌리면 대기가 2배가 된다):

```
codex exec --skip-git-repo-check -s read-only "$(cat {scratch}/q.md)" > {scratch}/codex_out.md
agy -p "$(cat {scratch}/q.md)" --effort high --print-timeout 15m > {scratch}/agy_out.md
```

codex는 표준출력이 버퍼링돼 완료 전까지 파일이 비어 있다 — 파일 크기가 아니라 **프로세스 종료**로
완료를 판정한다.

## ② 나도 판정한다

패널을 기다리는 동안 **메인 컨텍스트에서 직접 같은 질문에 답한다.** 이때 패널 출력을 먼저 읽지
않는다 — 읽고 나면 내 판정이 그쪽으로 끌려가고, 3자 교차가 사실상 2자가 된다.

원문뿐 아니라 **주변 자료**(작업폴더의 `research/`·이전 판본·연관 건)를 함께 본다. 패널은 인라인된
원문만 보지만 나는 폴더 전체를 볼 수 있다 — 교차의 값어치가 여기서 나온다.

## ③ 사실 대조 — 생략 금지

패널 출력이 다 오면 **먼저 대조부터 돌린다.** 읽고 나서 돌리면 이미 틀린 수치가 머리에 남는다.

```
python3 "$SKILL_DIR/scripts/verify_claims.py" {원문...} \
    --panel agy={scratch}/agy_out.md --panel codex={scratch}/codex_out.md
```

- exit 0 = 미검증 주장 없음, exit 1 = 있음(정상 동작), exit 2 = 인자·파일 오류
- `--window` 로 앵커 근접 반경(기본 400자)을 조정하고, `--json` 으로 기계 판독 출력을 받는다
- 두 가지를 잡는다: **수치-미검출**(원문에 없는 값) · **귀속-불일치**(값은 있으나 그 과제 것이 아님)

**스크립트가 못 보는 것은 내가 본다.** 아래는 판단이 필요해 결정론으로 내리지 않았다:

- **단위 없는 과장** — "수만 건", "압도적", "대부분"
- **인과 주장** — "A라서 B가 된다"가 원문에 근거가 있는가
- **원문에 있는 값의 오독** — 값도 맞고 과제도 맞지만 의미가 다른 경우

플래그된 항목은 전부 원문에서 직접 확인한다. **자기 제안 수치는 대조 대상이 아니다** — 패널이
"300~500h로 낮춰라"라고 권고한 값은 원문에 없는 게 정상이다. 원문 서술이라 주장한 것만 본다.

## ④ 종합

셋(또는 둘)의 판정을 이 순서로 낸다.

1. **판정 수렴표** — 패널별 한 줄 판정을 나란히
2. **합의 항목** — 독립적으로 같은 지점을 짚은 것. 교차검증의 신호는 여기다
3. **단독 주장** — 한 패널만 말한 것. 검증 후 채택하거나 기각하고, 기각이면 사유를 남긴다
4. **사실오류 표** — ③에서 걸러낸 것. 열: 주장 / 실제. **인용하면 반박당한다는 것을 명시**
5. **내가 단독으로 잡은 것** — 폴더 전체를 본 이점이 나온 지점

**패널 판정을 그대로 옮기지 않는다.** 확인한 것만 내 판정으로 낸다. 패널이 강하게 단정해도 원문
근거가 없으면 기각하고, 표현이 온건해도 근거가 맞으면 채택한다.

## 흔한 실수

| 실수 | 결과 |
|---|---|
| 원문 파일 경로만 주고 인라인 생략 | 패널이 파일을 못 읽고 추측으로 답한다 — 티가 안 난다 |
| 패널 출력을 먼저 읽고 내 판정 | 3자 교차가 2자로 줄고, 첫 패널 프레임에 갇힌다 |
| ③을 건너뛰고 종합 | 지어낸 수치가 그대로 보고서로 간다. 이 스킬을 쓰는 이유가 사라진다 |
| 플래그를 전부 오류로 처리 | 패널의 제안 수치·외부 준거는 원문에 없는 게 정상이다 |
| 다수결로 판정 | 두 패널이 같이 틀릴 수 있다. 근거가 판정하지 표수가 판정하지 않는다 |

## 참조

- `scripts/verify_claims.py` — 수치 근거 대조. JSON 출력, exit 0(통과)/1(미검증 있음)/2(오류)
- report-pipeline `references/factcheck.md` — 전수 팩트체크 절차(§A). 이 스킬의 ③이 그 경량판이다
