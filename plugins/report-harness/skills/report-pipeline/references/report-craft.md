# 보고서 설계 지침 (report-craft)

> **무엇을 어떤 순서로 세우나** — 목적·결론·근거 구조를 정하는 기준이다. 문장을 어떻게 쓰나(계층·종결·표기·쉬운 말)는
> `style-guide.md`, 변환 문법은 `md-profile.md`, 개별 규칙은 `rules.md`가 정본이다. **이 문서와 기관 규정이 부딪히면 기관
> 규정이 이긴다** — 예: 일반 개조식 교재는 `~함·~임·~됨` 종결을 권하지만 기관 철칙은 동작명사 종결이다(style-guide §4).
>
> 원천은 claudian 위키에 '26.7.15 수집한 보고서 작성법 자료 8건과 개념 문서(한 장 보고서·피라미드 원칙·A3 보고서·
> 아마존 내러티브 메모)다(§5). 원문을 옮기지 않고 원칙만 우리 말로 다시 썼다 — 위키가 없는 설치에서도 이 문서만으로 따른다.

## 0. 세 산출물과 적용 시점

| 시점 | 산출물 | 이 문서 | 칸 검사 |
|---|---|---|---|
| 게이트⓪ 끝 | `00_context.md`의 `## 보고 설계` | §1 | `check_craft.py context {work_dir}` |

## 1. context — 보고 설계 (`00_context.md`)

보고서를 쓰는 내내 되돌아볼 기준을 먼저 정한다. 가장 흔한 실패는 목적을 잊은 채 자료를 늘어놓는 것이고, 가장 비싼
실패는 착수 뒤에야 상황 전제(이미 발주했다·대응할 지적이 있다·상위 계획서가 있다)가 드러나 논지를 통째로 버리는 것이다.

- **목적을 한 줄로** — "무엇을 결정받는가 / 무엇을 알리는가". 보고 목적이 제목과 같으면 본문 '목적' 단락은 생략해도 된다.
- **결재자 기준으로** — 누가 읽고 무엇을 정하는가. 경영진은 핵심 수치와 전체 흐름, 실무자는 세부 방안을 먼저 찾는다.
- **결론은 과제에 대한 답** — 분석이 끝나기 전이라도 예상 결론을 한 줄로 적는다(가설). 뒤집히면 정정 줄을 덧붙인다.
- **상황 전제를 먼저 확인** — `05_analysis.md`로 답이 명확하면 채우고, 불명확할 때만 게이트⓪에서 묻는다(4문항 상한은
  명확한 문항을 건너뛰어 지킨다).

게이트⓪ 답을 받은 뒤 `00_context.md`에 아래 블록을 **한 번** 덧붙인다(이후 바뀌면 정정 줄을 새로 덧붙인다):

```
## 보고 설계
- 보고 목적: {이 보고로 얻으려는 것 1줄}
- 결재자·수신자: {직위·역할 — 실명 제외}
- 결재자가 내릴 결정: {승인·선택·인지 중 무엇을 — 선택지가 있으면 나열}
- 예상 결론: {한 줄 가설 — 제목 후보}
- 상황 전제: {의사결정 전/후(발주·계약 여부) · 대응할 외부 제기·지적 원문 · 먼저 받을 내부 상위 계획 문서 — 없으면 "없음(확인함)"}
```

## 2. outline — 설계 점검 (`10_outline.md`)

- **제목이 곧 결론** — 제목만 읽어도 결론을 알게 한다. 기관 제목 규칙(명사구 + 문서유형 접미, style-guide §1) 안에서
  결론을 명사구에 담는다(예: "검수 시간을 포함한 AI 성과 측정 체계 마련 방안").
- **피라미드로 세운다** — 사고는 사실에서 결론으로 올라가지만 전달은 결론 → 근거 → 사실로 내려간다. 핵심 메시지
  1~2줄 아래에 근거 2~4개를 두고, 근거끼리 겹치지 않고 빠진 것이 없게(MECE) 나눈다. 깊이는 □ → ㅇ → - → ※ 네 단계를
  넘기지 않는다.
- **절마다 So What / Why So** — 절이 "그래서 무엇을 뜻하나"를 한 줄로 말할 수 없으면 나열이다. 그 한 줄을 받치는
  근거("왜 그런가")가 근거 목록에 있어야 한다 — 없으면 논리 비약이다.
- **구성요소를 대조한다** — 목적·현황·핵심 메시지·대안·결론·향후계획. 문서 유형(style-guide §0)에 따라 빠질 수 있지만
  빠뜨린 것은 사유를 한 줄 남긴다(예: "대안 X — 단일안 확정 보고").
- **상위 계획 요건과 1:1** — 상위 계획서(협의체 추진안·실행과제·과제관리카드 등)가 있으면 그 산출물 요건 ↔ 절 대응표를
  먼저 보이고 빈 요건이 없게 한다.
- **억지 추진과제를 만들지 않는다** — 과제 수·형식을 채우려 만든 항목은 뺀다. 실무에서 바로 쓸 수 있는 것만 둔다.
- **성과 지표는 결과 단계로 세운다** — 대표 지표는 시간·비용·정확도·처리 방식의 변화 같은 결과·영향 지표로 두고,
  처리 건수 같은 규모(산출) 지표는 관리지표로 병기한다. 정부 AI 성과지표 Pool도 처리 건수를 산출 단계로 나누고,
  경영평가는 '단순건수 등 산출지표'를 개선 대상으로 본다('26.9.25 1127 f16 — 업무량 지표를 AI 처리율로 전환).
- **분량은 사용자가 정한다** — 아웃라인 단계에서 내용을 빼지 않는다. 넘치면 붙임·참고자료 배치를 선택지로 제안한다.

`10_outline.md`에 아래 블록을 둔다(게이트①에 함께 보인다):

```
## 설계 점검
- 제목(결론): {제목 후보}
- 핵심 메시지: {1~2줄}
- 근거 구조: ① … ② … ③ … (겹침·누락 점검 결과 1줄)
- 절별 So What:
  - □ {절 제목} — {이 절이 뜻하는 것 1줄}
  - □ …
- 구성요소: 목적 O · 현황 O · 핵심 메시지 O · 대안 X(사유) · 결론 O · 향후계획 O
- 상위 계획 대응: {없음(확인함) 또는 요건 ↔ 절 대응표 위치}
```

## 3. draft — 집필 자가감사 (`20_draft.md`)

기존 결정론 검사(lint·audit)가 잡는 것은 다시 적지 않는다 — 두괄식(절 첫 ㅇ 결론, R091 `lead-not-conclusion`)·한 항목
한 문장(style-guide §3)·쉬운 말(R091)·도식 문장(R093)·외부 인용 출처(R092). 여기서는 사람이 판단해야 하는 것만 본다.

- **배치** — ㅇ의 괄호 리드는 키워드, 본문은 사실, 끝 괄호는 판단을 돕는 수치·기준(style-guide §2 괄호 리드와 같은 구조).
- **개조식의 약점을 막는다** — 명사형 종결은 시제·주체·논리 관계를 흐린다.
  - 시제: 끝났는지·할 것인지가 갈리면 시점을 적는다(`'26.10월`, 완료·예정).
  - 주체: 누가 하는지 적는다(부서·기관·위원회).
  - 논리 관계: 이유·조건·대조는 대시 문장 안에서 잇는다(`~해 ~`, `~하되 ~`) — 한 문장 이음 3개 미만(R091 `clause-chain`).
  - 인과가 길게 얽혀 개조식으로 끊으면 뜻이 사라지는 대목은 서술형 문단을 붙임으로 둔다.
- **흔한 실수 점검표**(게이트② 제시 전 1회, 걸린 항목만 고친다)
  1. 사실 없는 상상 — 근거 목록에 없는 주장·수치가 있는가(수치는 `numbers` 검사, 두 자리 수치는 원문 대조).
  2. 실행 없는 의미 부여 — 결론·향후계획에 누가·언제·무엇을이 있는가.
  3. 진부한 답 — 이 기관·이 과제에만 해당하는 수치·판단이 들어 있는가.
  4. 불리한 사실 감추기 — 빼지 말고 대응책과 함께 적었는가.
  5. 날짜·단위·중복·누락 — 같은 값이 절마다 다르게 적히지 않았는가.
  6. 욱여넣기 — 글자를 줄여 채우지 않았는가(넘치면 붙임으로, R028).
- **분량보다 내용** — 게이트⓪에서 고른 분량에 맞추려고 근거 대시·※·표를 임의로 빼지 않는다. 넘치면 1줄로 알리고
  줄일 곳은 사용자가 고른다.

## 4. 판단은 선택지로 (전 단계 공통)

- 판단이 갈리는 지점(논지 방향·지표 성격·포함 범위·분량 조정)은 작성자가 정하지 않고 선택지로 묻는다.
- 사용자 결정이 논지와 부딪히면 부딪힌다는 사실을 밝히고 다시 확인한다.
- 결재자의 수정 지시가 방향 없이 맴돌면(A→B→A) 판단 지점을 선택지로 좁혀 묻는다.
- 사람은 실명 대신 담당 업무로 적는다.

## 5. 원천 (claudian 위키 — 선택 결합)

| 자료 | 이 문서에 쓴 것 |
|---|---|
| 박신영, 「한 장 보고서의 정석」(서적 요약) | 목적 상기, 핵심 파악 → 구조화 → 명료한 문장 |

| 개조식 문서 작성 실무(eunhah) | 전례 형식, 목적과 제목이 같으면 목적 단락 생략, 내용 중립 |
| 개조식의 기원과 비판(brunch) | 시제·주체·논리 관계 흐림 → §3 보완 |

| 핵심문구 작성법(publy) | 핵심 메시지 1~2줄, 결론 먼저 |
